- [ ] 存储失败显示未持久化状态；不能仅凭完成解析标为“已保存”。
- **验收：** 浏览器刷新、存储空间不足、旧schema迁移、恢复备份均有明确结果；旧版数据库不被读取覆盖。
- **位置／依赖／工作量：** storage、types、导入界面；P0-01；2–3日。

### P1-08 导入取消、进度与并发保护

**依据：代码已确认。** 当前 Worker 每次处理一个导入任务，但缺少完整取消、进度阶段和竞态保护设计。

- [ ] 增加读取、解压、解析、校验、保存阶段；没有真实总量时不用伪百分比。
- [ ] 支持取消并终止Worker，超时后释放资源并保留旧数据。
- [ ] 用任务ID保证后发任务不会被前一个晚完成结果覆盖。
- [ ] 防止初始IndexedDB恢复结果覆盖用户刚导入的数据。
- **验收：** 连续导入A/B、取消大文件、启动期间立即导入、失败重试均不会串数据。
- **位置／工作量：** import-client、import-worker、page；1–2日。

### P1-09 性能基准与查询索引

**依据：代码已确认，耗时影响待量测。** 多处按考试、类别、学生反复 filter/find，报告和知识点聚合可能重复扫描。

- [ ] 建立可复现的合成规模：约1千、1万、5万成绩记录及不同小题规模。
- [ ] 分别测解析、首次展示、筛选、报告生成、峰值内存，记录机器与浏览器。
- [ ] 建立考试／班级／学生／分数线索引，按数据集版本失效缓存。
- [ ] 大名单分页或虚拟列表；避免为每次筛选重建全量历史图表。
- **验收：** 指定参考设备上，约1万记录常规筛选目标P95不超过300ms；目标需先测基线再确认，不能作为当前性能承诺。
- **依赖／工作量：** P0统计模型稳定后；2–3日。

### P1-10 学生检索与筛选联动

**依据：代码已确认。** 学生搜索有先截80、再展示20的逻辑，可能限制未充分搜索时的可见范围。

- [ ] 搜索姓名、学号、班级；清晰显示命中总数并分页。
- [ ] 切换考试、类别、班级后清除不兼容的选中学生和学科，或明确恢复规则。
- [ ] 支持可见的排序、重置筛选和当前筛选摘要。
- **验收：** 超过80个匹配结果仍全部可达；类别切换后不残留不属于当前范围的学生画像。
- **位置／工作量：** page、检索组件；1–2日。

### P1-12 手机端与可访问性专项验收

## 6. P2：长期可维护与扩展

### P2-01 页面模块拆分与公共计算接口

### P2-02 版本清单、候选发布和快速回退

- [ ] 每版产物附manifest和校验值，保留可回退版本。
- [ ] 发布前比较既有路径资源，确认不会意外替换或删除旧版本。
- **验收：** 一个新版本失败时已部署旧页继续可用；回退不依赖恢复真实学生数据。

## 8. 实施前需要学校确认的业务信息

这些是开发规则的输入，不是要求用户现在逐项回答；可在实施对应模块前集中核对。

1. 17、18班真实班型；其他班型是否随学期改变。
2. 7班外语、9班选科映射在各次考试是否始终适用。
3. 每次考试日期、满分、原分／赋分方式及总分组成。
4. “物有效／历有效”和“(2)”各自用途，谁作为正式上线统计口径。
5. 缺考、缓考、转入转出、体育艺术学生的统计分母规则。
6. 是否有稳定学号及历史转班对照；无法提供时允许哪些匹配方式。
7. 学科“有效人数”指单科达线人数，还是还要求总分达线；若两者都需要，应分别命名。
8. 报告主要面向年级会议、班主任辅导还是对外沟通，决定摘要／全量与身份字段范围。
