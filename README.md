# 数据准确性修复版 v1.1.0

独立地址： https://yusheng266186-beep.github.io/zhiliang-huixi-new-/accuracy-v1.1/

此分支基于原 main 版，保留原界面。根路径及 /v2/ 保留原来源版本，新版使用独立 IndexedDB，不覆盖旧版数据。

## 修复内容

- 新导入默认最新已知考试，保存考试选择；已知考试代码按学期顺序排列，未知名称保留来源位置，日期和满分未提供时不推断。
- 补充17班物化生、18班历政地，班型保持待配置；未知班级按考试类别选择学科，汇总沿用类别；待配置班型不进行跨班型比较。
- 小题表使用自己的学科来源；9班地理读取地理工作表，不使用生物题目。日语缺少独立题目时不借用英语题库。
- 小题筛选同时应用考试、类别、班级和有效学生范围。当前考试无小题时显示缺失提示。
- 源表缺少小题满分时保留平均得分，不使用观测最大值充当满分，不生成正式得分率、知识点补弱结论。
- 无分数线显示不可计算；有部分分数线时仅使用可计算学生作分母。重建总分不进入正式上线统计。
- 页面、Word、PDF和Excel分析模型统一口径，未知数值显示横线或空白，避免输出NaN。
- 历次观察限于当前考试及之前，展示同校同班同名同类别匹配人数与总分/距线变化；不将原始均分变化称作教学增值。
- Excel解析移至Web Worker，限制小题读取列宽；浏览器保留响应，失败不覆盖已载入数据。

`npm run test:accuracy -- /path/to/workbook.xlsx` 可在本机核验这次51工作簿的分类人数、上线人数、17/18班、9班地理及本次小题缺失。真实工作簿不提交仓库。

## 仍需学校确认的信息

17、18班班型未由表格确认，标为待配置；历次考试日期和满分需学校提供。学生历史匹配使用姓名与班级，转班和重名需要人工核验。分数线优先采用学生基础表，不擅自合并“有效(2)”的其他口径。

# 质量慧析 · 考试质量分析系统

本地优先的考试质量分析系统。导入质量复盘 Excel 后，可以从年级、考试、类别、班级、学科和学生多个层次进行分析，并导出可交付的 Word、PDF 和 Excel 报告。

> 在线 Pages：[打开质量慧析](https://yusheng266186-beep.github.io/zhiliang-huixi-new-/)  
> GitHub：[查看源代码](https://github.com/yusheng266186-beep/zhiliang-huixi-new-)

## 项目定位

质量慧析把原始考试工作簿转换为可解释的教学分析结果，适合用于：

- 年级考试质量复盘；
- 班级横向对比；
- 学科有效人数和达线情况分析；
- 临界生与薄弱学科诊断；
- 学生画像和历次考试对照；
- 小题得分率与知识点优先级分析；
- 导出会议、教研和班级沟通所需的分析材料。

Pages 版本在浏览器本地解析 Excel、生成图表和导出文件，不依赖服务器端数据库。

公开页面启动时可以调用内置的虚构示例成绩生成器，用于展示界面和交互；真实工作簿不会随仓库发布，只有在浏览器中选择并确认上传后才会进入当前设备。上传的工作簿默认只在当前浏览器环境中处理和保存，不会写入公开仓库。

## 主要功能

### 考试质量总览

- 年级总成绩；
- 一本、本科上线人数和上线率；
- 学科有效人数与有效率；
- 分数分布光谱；
- 重点指标和证据驱动洞察。

### 班级与类别分析

- 物理类、历史类分别查看；
- 班级横向对比；
- 同类班级基准；
- 班级均分、达线率和学科表现；
- 班级薄弱学科及优先行动方向。

### 学生分析

- 学生画像；
- 历次考试变化；
- 总分和学科趋势；
- 临界生名单；
- 薄弱学科诊断；
- 学生分层行动栈；
- 根据证据生成教学关注点。

### 小题和知识点

- 小题得分率；
- 知识点表现；
- 学科能力矩阵；
- 知识点优先级；
- 题目、知识点和学生表现的关联分析。

### 报告导出

- 详细 Word 报告；
- 分页 PDF 报告；
- 多工作表 Excel 分析包；
- 可将报告用于年级复盘、班级沟通和教研留档。

### 数据健康与容错

- 语义表头识别；
- 字段映射提示；
- 自动去重；
- 缺失字段降级；
- 缺失总分时按规则重建；
- 损坏文件和不完整工作簿保护；
- 对数据置信度进行提示。

## 当前数据口径

项目使用脱敏或虚构数据进行解析和分析测试；实际学校规则仅在本地导入后按需配置：

- 支持外语字段按本地规则重映射；
- 支持学科及小题字段按本地规则重映射；
- 物理类和历史类混合查看时，每名学生按自己的类别分数线判断上线；
- 不使用物理类、历史类平均分数线替代个人类别分数线；
- 缺失总分时，至少有4门有效学科才重建，并标记为“重建”；
- 缺失学科不会按0分参与均值；
- 学生基础表改名、插入空列、字段改名或缺失小题表时，系统按语义表头继续工作，并降低对应模块置信度。

## 启动开发环境

要求：

- Node.js >= 22.13.0；
- npm；
- 支持现代 JavaScript、TypeScript 和浏览器 API 的开发环境。

安装依赖：

    npm install

启动开发服务器：

    npm run dev

默认打开终端显示的本地地址，通常是：

    http://localhost:5173

## 常用命令

    npm run build:pages
    npm run lint
    npm run test
    npm run test:parser -- "/path/to/质量复盘.xlsx"
    npm run test:analytics -- "/path/to/质量复盘.xlsx"

说明：

- build:pages：构建 Pages 静态站点；
- lint：检查代码质量（typescript-eslint + react-hooks）；
- test：构建 Pages 并执行产物冒烟检查（入口 HTML 与本地资源引用必须可解析）；
- test:parser：验证工作簿解析、字段映射和容错；
- test:analytics：验证统计分析和指标结果。

验收覆盖多考试、多分数线、缺失字段和小题记录等场景。

解析和分析脚本还会测试插入空列、字段改名、缺失学科、缺失总分和缺失小题表等变体。
不带参数时默认使用 `examples/synthetic-quality-review.xlsx`（由 `scripts/make-fixture.ts`
从真实工作簿生成的匿名合成示例，本机生成、不入库）；分析真实数据时通过参数显式传入。

## 目录结构

    zhiliang-huixi-new-/
    ├── app/                  # 前端页面、组件、分析逻辑和导出功能
    ├── examples/             # 合成示例的生成说明（工作簿本身不入库）
    ├── pages-static/          # GitHub Pages 静态入口和发布资源
    ├── public/                # 公共资源
    ├── scripts/               # 解析、分析、验证与构建冒烟脚本
    ├── .github/workflows/     # Pages 发布工作流
    ├── package.json           # 脚本和依赖
    └── vite.pages.config.ts   # 开发与 Pages 静态构建配置

这是一个纯客户端单页应用：解析、分析、图表与导出全部在浏览器完成，无服务端组件。

## GitHub Pages 发布

仓库内置 .github/workflows/pages.yml。推送到 main 后，工作流会：

1. 安装 npm 依赖；
2. 执行 `npx tsc --noEmit` 与 `npm run lint` 质量门；
3. 执行 npm run build:pages；
4. 运行构建冒烟检查（scripts/check-pages-build.mjs，入口 HTML 与全部本地资源引用必须可解析）；
5. 发布到 GitHub Pages。

Pages 地址：

    https://yusheng266186-beep.github.io/zhiliang-huixi-new-/

Pages 版本使用浏览器端处理 Excel、图表和 Word/PDF/Excel 导出，不依赖服务器端数据库。发布失败时，先检查 Actions 日志，再检查 pages-static、vite.pages.config.ts 和构建输出。

## 数据隐私与安全

这是教育数据项目，使用真实成绩时必须谨慎：

- 不要把包含真实姓名、学号、手机号或身份证号的工作簿提交到公开仓库；
- 不要把导出的学生报告上传到公开 Pages；
- 公开演示时使用脱敏或虚构数据；
- 本地浏览器 IndexedDB 中的成绩数据可能被同一设备上的浏览器配置访问；
- 共用电脑或公共浏览器使用后，应清除站点数据；
- 分享截图、报告和链接前，检查是否暴露学生身份；
- 若要给学校或年级正式使用，建议部署到有身份认证和访问控制的内部环境。

## 开发建议

- 修改解析规则后同时更新 parser 测试和 README 中的口径；
- 修改指标定义时，记录计算口径和数据来源；
- 修改导出模板后测试 Word、PDF 和 Excel 三种输出；
- 修改 Pages 构建时同时测试本地开发和静态发布；
- 不要用缺失值填充0来掩盖数据质量问题；
- 对异常字段和低置信度结果保持可见提示。
